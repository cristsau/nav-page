# DOMO NAV 数据库工作区

状态：本地候选，未推送、未部署

## 能力边界

- 每个数据库归属于一个 NAV 用户；属性、视图、记录、关系和反向关联均通过数据库 ID 与用户 ID 的组合约束隔离。
- 关系同时保存来源数据库与目标数据库，并由 PostgreSQL 组合外键校验来源属性、来源记录和目标记录，不能跨用户或借用其他数据库的属性。
- 支持表格与看板视图、多个筛选和排序、可见属性、关系与反向关联、记录归档和恢复。
- 删除属性时，同一事务会移除记录里的旧值，并清理所有视图中引用该属性的筛选、排序、可见列和分组配置。
- 删除仍被记录使用的单选、多选或状态选项会返回冲突；关联属性已有数据时不能直接切换目标数据库。

## 记录加载硬上限

单次记录列表请求按 `position, created_at, id` 排序读取至多 5,001 条，仅返回前 5,000 条，并用 `limit=5000`、`hasMore=true`、`truncated=true` 明确告知客户端结果已截断。

视图筛选与排序当前在这批已加载记录上执行，因此不会覆盖第 5,001 条以后的记录。界面必须显示硬上限提示，不能暗示筛选能找到未加载的数据。需要完整处理时，应先归档或拆分数据库；服务端分页和服务端筛选属于后续扩展，未实现前不得声称支持无限记录。

## 发布门禁

发布前必须在一次性 PostgreSQL 16 数据库中：

1. 连续执行两次全部迁移，确认 `044_email_protocol_reconciliation.sql` 与 `045_workspace_databases.sql` 只登记一次；
2. 运行 `verify:migrations`，验证 045 的精确列、约束、组合外键和索引定义；
3. 运行数据库工作区 PostgreSQL 集成测试，覆盖租户隔离、关系/反向关联、属性配置兼容、视图修复、归档/恢复、筛选/排序、并发序列化和 5,000 条硬上限；
4. 运行前端构建并在桌面与手机尺寸人工检查表格横向滚动、看板、弹窗焦点、触控尺寸和截断提示。
