# NAV AI 确认式操作

状态：本地开发完成，未发布。

## 能力

助理可先列出当前登录用户拥有的候选，再为以下操作生成确认卡：

- 修改或删除笔记、书签、导航分组；
- 创建或撤销笔记分享；
- 创建邮件草稿，或把既有草稿加入本地发送队列；
- 创建、修改或归档工作区数据库记录。

旧有的日记、备忘录、书签和分组创建仍只在用户当前消息明确要求时立即执行。其他操作不会在模型首次调用时执行。

## 安全状态机

1. 模型先调用只读候选工具。目标 UUID 必须原样来自本轮候选。
2. 服务端在事务内再次校验当前用户所有权、资源状态和关系目标库。
3. 服务端写入 15 分钟有效的 `awaiting_confirmation` proposal，并返回预览。
4. 用户可确认或取消；确认、取消和已成功结果都支持网络重放而不重复执行。
5. 可安全撤销的操作提供 10 分钟撤销窗口。撤销前比较执行后指纹；资源被用户继续修改时拒绝覆盖。

邮件收件人、主题、正文预览以及邮件操作参数均加密保存。发送确认只在同一数据库事务内写入本地 outbox；实际投递由邮件 worker 完成，未知投递结果不会由助理自动重试。

## API

- `POST /assistant/actions/:operationId/confirm`
- `POST /assistant/actions/:operationId/cancel`
- `POST /assistant/actions/:operationId/undo`

三个接口都只操作当前登录用户的 operation。确认使用持久 operation ID、参数摘要和状态锁防重放。

## 数据库

迁移 `046_assistant_confirmed_operations.sql` 新增 proposal payload 表，保存有界参数、预览、过期时间、执行前快照、执行后指纹和可选加密载荷。该表通过 `(user_id, operation_id)` 关联 durable receipt/audit 主表。

## 边界

- 加密笔记不可公开分享；非普通文本笔记不可由助理修改。
- 含书签的分组不会被助理删除。
- 工作区 relation 必须属于当前用户和属性声明的目标数据库，并同步关系索引。
- 邮件草稿内容变化后，旧确认摘要失效。
- 邮件发送、删除、撤销分享和归档都必须单独确认。
