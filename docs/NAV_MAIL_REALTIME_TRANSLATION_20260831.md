# DOMO NAV — 邮件低延迟收取与附件 AI 翻译

状态：`LOCAL_DONE / READY_FOR_CI / NOT_DEPLOYED`

基线：`955fb5c3`（记录方案时的 `origin/master`）

日期：2026-08-31

## 1. 目标与现状

本批解决两个独立但相邻的问题：

1. 新邮件虽然已有 IMAP IDLE 与 60 秒轮询兜底，但同一收件循环仍按顺序执行“抓取、解析、
   加密入库、AI 分类、通知”。AI 请求最长可以等待 45 秒，一批邮件也只取有限数量，因此 AI
   或积压可能放大用户看到新邮件的延迟。
2. 邮件正文已经支持 AI 翻译；用户新增需求是翻译邮件附件中的内容。现有附件下载接口只在
   用户点击后从 IMAP 拉取目标附件，返回后清除服务端缓冲区，并不会提取或发送附件内容给 AI。

本文件同时记录实施结果、剩余待办和验收契约。P0 本地源码已经完成，仍需通过 GitHub 的真实
PostgreSQL 16 集成门禁并经单独授权发布；P1 保持独立评审、测试、发布和回滚。

## 2. P0：先入库的低延迟收件流水线

### 2.1 入库与 AI 解耦

- IMAP worker 完成远端 UID 校验、受限抓取、本地解析和 AES-256-GCM 持久化后，应立即提交
  邮件位置与规范邮件，并发布不含正文的 SSE 元数据事件。
- AI 分类、通知规则判定和通知投递进入 PostgreSQL 持久任务队列；AI 慢、限流、失败或进程
  重启不得阻塞后续 UID 入库，也不得让已经安全保存的邮件从工作台消失。
- 队列以用户、邮箱账户、规范邮件和任务类型建立唯一幂等边界，状态至少区分
  `pending`、`running`、`retry_wait`、`succeeded`、`dead_letter`；重试次数、下次执行时间、
  泛化错误码和敏感载荷清理必须受数据库约束。
- 分类任务从已加密保存的规范邮件读取输入。邮件正文继续视为不可信外部数据；任务和日志
  不得保存明文正文、附件、密码、Token、模型提示或完整邮箱地址。
- 当前迁移 ledger 截止 `041_email_remote_commands.sql`。P0 的第一份结构迁移命名为
  `042_email_ingest_pipeline.sql`，必须为加法迁移并允许应用回滚后保留结构。

### 2.2 连续有界排空

- 一轮因批量上限或原文预算结束但尚未追平 `UIDNEXT` 时，worker 应立即请求下一轮，而不是
  固定等待轮询周期。
- 连续排空必须设置单次时间片、最大连续轮数和让步间隔，避免大邮箱积压长期占用事件循环或
  数据库连接；失败使用有上限的指数退避和 jitter。
- IMAP IDLE 继续作为新邮件触发源，定时轮询继续作为断线和漏事件补偿。连接关闭后重连不得
  清空已持久游标，也不得重复创建邮件或通知。

### 2.3 API 到 worker 的立即同步

- 邮件页“立即同步”只向 PostgreSQL 写入/发布一个绑定当前用户与邮箱账户的唤醒请求；API
  进程不得另开 IMAP 同步循环。
- 只有持有现有 PostgreSQL advisory lease 的 `nav-mail-worker` 可以消费唤醒并连接 IMAP。
  多次点击、双域并发和重放使用数据库 generation 与 5 秒窗口合并；接口执行认证、运行时账户
  归属检查并返回 `202 Accepted` 状态语义。
- 页面显示“已请求、同步中、已追平、失败后重试”这些真实状态；不能把请求已接受写成邮件已
  收取成功。

### 2.4 可观测性

- 已记录不含邮件内容的时间点、数量和泛化状态：触发、入库成功、同步请求/完成、AI 分类
  完成、队列积压、最旧待处理年龄、最大处理延迟和最后错误码。
- 当前管理员维护状态已提供最近成功、积压和有界延迟指标；连接重试次数与滚动 p50/p95 留作
  后续观测增强，不作为本批已经完成的能力。所有指标不得包含主题、正文、附件名、发件人或收件人。
- 在同区域、连接健康且无历史积压的受控测试中，以 worker 收到 IMAP `EXISTS` 为起点、规范
  邮件提交并发布 SSE 为终点，目标 p95 不超过 15 秒。AI 分类完成时间单独计量，不纳入邮件
  首次可见门槛。

## 3. P0：安全文本附件 AI 翻译

### 3.1 首期范围

- 仅在已认证用户打开自己拥有的邮件并明确点击“翻译附件”后处理，不在收件、预览或列表阶段
  自动下载附件。
- 首期接受明确 allowlist 的文本/结构化 MIME，例如 `text/*`、JSON、XML、CSV 与 Markdown；
  `application/octet-stream` 仅在扩展名属于文本 allowlist 时接受。内容仍须通过严格 UTF-8
  解码和二进制控制字符检查，否则返回可理解的“不支持此格式”。
- 服务端先复用 UIDVALIDITY、UID、稳定附件 ID、大小和当前用户归属校验，再以受限缓冲区提取
  文本。二进制原件不得直接发送给模型，处理结束后必须覆零可控 Buffer。
- 单个附件上限为 512 KiB，交给模型的文本上限为 12,000 字符；超限会明确拒绝并要求用户
  缩小文件，不会静默截断后声称完整翻译。
- API 保留目标语言参数，首期界面提供中文翻译。译文在邮件详情中与原附件元数据并列显示，
  可重新生成或关闭，但不会
  修改、覆盖、移动或回传原邮箱附件，也不会自动保存成 NAV 笔记或发送邮件。

### 3.2 AI 与隐私边界

- 附件文本与邮件正文一样属于不可信外部数据；其中任何命令、提示、链接或“系统消息”都不能
  改变翻译任务、调用工具、联网或授权写操作。
- 发送给模型前继续执行敏感值脱敏，翻译请求使用邮件 AI 共享限流、用量记录和 45 秒超时。
  审计只记录用户、资源类型、动作、结果、模型和数量，不记录附件名或内容。
- 首期不持久化原附件内容或译文，因此不需要为附件翻译单独新增数据库迁移。若以后需要缓存，
  必须另行设计加密、TTL、内容版本绑定和清理，不得复用明文缓存。

## 4. P1：远端状态对账与复杂文档提取

### 4.1 CONDSTORE/QRESYNC

- Provider 宣告支持时，使用已保存的 `UIDVALIDITY`、`highest_modseq` 和位置 `modseq` 增量
  对账已读、星标、关键词与 expunge；能力缺失时保留有界 UID/flags 校准路径。
- `UIDVALIDITY` 改变、VANISHED、移动与远端删除必须按目录位置处理，不能误删同一规范邮件在
  其他目录的位置，也不能把本地缓存状态冒充远端成功。
- 多目录周期同步、命令 outbox 与被动对账必须共用冲突规则和幂等身份；未知网络结果保持
  `conflict/reconcile`，不盲目重复写远端。

### 4.2 PDF/Office 安全文本提取

- PDF、DOCX、PPTX、XLSX 仅在单独安全评审后加入 allowlist。解析必须在无网络、受 CPU/内存/
  时间/文件数限制的隔离进程或容器中运行；拒绝加密文件、宏、外部关系、嵌入对象和压缩炸弹。
- PDF 首期只读取已有文本层；不做 OCR。Office 只提取单元格、段落、幻灯片等纯文本，不渲染、
  执行或加载远程资源，并保留页码/工作表/幻灯片来源标识。
- 复杂文档翻译仍只返回可审阅文本，不生成“看似保持原版式”的文件，不覆盖原件，也不宣称
  已翻译未解析或被截断的内容。

## 5. CI 与定向验收

P0 合并前至少需要：

1. 单元测试证明 AI 人为延迟 45 秒或失败时，连续多封邮件仍先后入库，游标不会因分类失败被
   阻塞，分类任务随后可恢复且通知不会重复。
2. PostgreSQL 16 集成测试连续执行两次迁移 `042`，验证队列归属、唯一幂等、抢占、重试、
   进程重启恢复、失败终态、级联删除和迁移验证器。
3. 积压超过单批上限时连续有界排空，不等待 60 秒；时间片结束会让步并自动续跑。
4. 双域并发“立即同步”只唤醒持有 lease 的 worker；未认证、跨用户账户、超限和重放均拒绝
   或合并，API 进程不创建 IMAP client。
5. 文本附件翻译覆盖正常 UTF-8 文本、声明/内容不一致、非法编码、超限、UIDVALIDITY 改变、
   附件替换、跨用户访问、模型超时、提示注入和 Buffer 清理；数据库、响应外字段和日志中无
   明文附件或 Secret。
6. API 全量测试、邮件 PostgreSQL 16 集成、迁移重复执行与验证、前端生产构建、无障碍检查、
   `git diff --check` 和秘密特征扫描全部通过。

P1 还必须增加真实支持 CONDSTORE/QRESYNC 的测试邮箱演练，以及针对每个新增文档解析器的
恶意样本、压缩炸弹、超时、内存上限和无网络证明。
