# DOMO NAV — 加密邮箱同步与只读工作台

状态：`LOCAL_DONE / READY_FOR_CI`。本文件描述迁移 `035_email_mailbox_foundation.sql` 引入的首期能力；在 GitHub CI、隔离 PostgreSQL 16 演练和真实 IMAP 验收完成前，不应启用生产收件任务。

## 本期交付边界

- 邮箱工作台为只读视图：可以查看账户、已同步文件夹、邮件列表和邮件正文，不会回复、转发、移动、标记或删除原邮箱邮件。
- 独立 `nav-mail-worker` 使用 IMAP IDLE 加定时轮询同步配置的邮箱目录，默认是 `INBOX`；目录清单可以发现，但只有完成实际同步的目录才会展示在界面中。
- 首次最多回看最近 `1000` 封邮件，此后按 UID 游标增量获取，每批默认 `100` 封。单封原始邮件默认最多处理 `512 KiB`，超过上限时只保存安全摘要所需字段；原文逐封拉取、处理后立即覆零，每轮默认最多读取八封上限的原文且硬上限为 `16 MiB`。
- 只展示纯文本正文。HTML 远程资源不加载，附件只保存元数据，不保存附件内容。
- 桌面端采用账户、邮件列表、正文三栏布局；手机端在列表和正文间切换，文件夹选择使用可关闭、可聚焦的底部面板。
- 页面实时更新使用 SSE；服务器进程只维持一个 PostgreSQL `LISTEN` 连接并向当前用户会话扇出元数据事件。每个用户的每个邮箱账户最多保留三条流，慢连接出现背压时主动断开；连接最长保留五分钟后重新认证，断线时退回定时刷新。

## 数据与安全模型

- 邮件信封、地址、主题和正文使用独立邮箱密钥进行 AES-256-GCM 加密；数据库只明文保存归属、目录、UID、时间、状态和不可逆哈希等检索元数据，不保存 IMAP 密码或加密密钥。
- `email_messages` 保存账户内的规范邮件；`email_folder_messages` 保存目录位置和 UID 状态。网页及 API 使用目录位置 ID 作为可操作标识，避免同一封邮件出现在多个目录时产生歧义。
- 所有查询同时校验当前用户与账户归属；跨用户复合外键和级联约束由 PostgreSQL 强制执行。
- UIDVALIDITY 改变时会清理该目录的旧位置映射并重新同步，不会把旧 UID 与新邮箱状态混用。
- 新邮件先完成加密持久化和分类，再推进目录游标。单封异常邮件最多重试三次；达到上限后只有在加密死信占位和位置标记均已持久化时才推进，避免毒邮件永久堵塞后续收件，也不会把原始异常或正文写入日志。
- 推送到浏览器的 SSE 载荷只包含位置 ID、规范邮件 ID、变更类型和修订时间，不包含发件人、主题或正文。
- 邮件页面的请求按账户和目录做代次隔离；用户切换、注销或离开邮件页时清空内存中的账户列表、分页结果和已解密正文。

## 运行拓扑

同一个精确发布 SHA 构建的 API 镜像分别承担两个角色：

- `nav-api`：`NAV_EMAIL_RUNTIME_ROLE=api`，提供 HTTP API、SSE 和管理配置。
- `nav-mail-worker`：`NAV_EMAIL_RUNTIME_ROLE=worker`，无对外端口，持有 PostgreSQL advisory lease 后执行 IMAP 同步。

worker 在启动前验证迁移后的四张核心表，并通过只读心跳文件提供容器健康检查。`nav-api` 健康后 worker 才启动，从而保证迁移先于收件任务。

## 上线所需配置

生产值只能写入 release 外部配置或只读 Secret 文件，不得进入 Git、PR、日志或聊天记录。

- `NAV_EMAIL_INGEST_ENABLED=false`：首次发布保持关闭，完成真实 IMAP 验收后再逐步开启。
- `NAV_EMAIL_SOURCE_KEY`：邮箱来源稳定标识，默认 `mxroute`。
- `NAV_EMAIL_OWNER_USERNAME`：邮件数据所属的已批准 NAV 用户名。
- `NAV_IMAP_HOST`：邮箱服务商提供的真实服务器主机名。
- `NAV_IMAP_PORT=993`、`NAV_IMAP_SECURE=true`：仅允许 TLS 1.2+ 的隐式 TLS。
- `NAV_IMAP_USERNAME`：完整邮箱地址。
- `NAV_IMAP_MAILBOX=INBOX`：首期唯一实际同步目录。
- `NAV_IMAP_INITIAL_LOOKBACK=1000`、`NAV_IMAP_BATCH_SIZE=100`。
- 每批原文预算由单封上限自动推导并限制在 `16 MiB` 内；该安全预算当前不作为普通 UI 配置项暴露。
- `imap-password`：IMAP 密码 Secret 文件。
- `email-encryption-key`：独立 32 字节随机密钥 Secret 文件；丢失后历史密文无法恢复，必须纳入加密备份。

GitHub CI 必须同时完成：

1. `docker compose ... config --quiet` 验证 API/worker 拓扑和挂载契约。
2. API 单元与契约测试全部通过。
3. 在一次性 PostgreSQL 16 中连续运行两次迁移、执行迁移验证器，并运行 `test:email-mailbox:integration`。

5. 前端构建通过。

生产验收还必须覆盖：

- 备份和隔离恢复成功后才执行迁移 `035`。
- `nav-mail-worker` 健康且与 `nav-api` 使用相同发布 SHA。
- 用真实邮箱完成连接、首次同步、增量收件和断线重连。
- 验证异常邮件重试/死信后后续 UID 仍可继续同步，并确认维护状态能够显示泛化错误码。
- 双域账户、目录、列表、详情和移动端交互一致。
- 多个登录会话可收到 SSE 更新，注销或会话撤销后最长五分钟内失效。
- 数据库、浏览器网络载荷和日志中不出现邮箱密码、密钥或可读正文。

## 回滚原则

- 首选关闭 `NAV_EMAIL_INGEST_ENABLED` 并停止 `nav-mail-worker`，API 可继续读取已经同步的数据。
- 应用回滚可以保留迁移 `035` 的新增结构；不要在没有可恢复备份前删除邮箱表或 `email-encryption-key`。
- 若 UID 或目录状态异常，先保留证据并停用同步，不直接清表或重置游标。
