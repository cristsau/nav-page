# NAV 云端数据安全恢复

> 状态：`READY_FOR_CI / NOT_DEPLOYED`
> 候选分支：`codex/nav-cloud-restore-guard-20260823`  
> 基线：`origin/master` `3e22a3a1951bc0c17f5d8482e62896e9a7b9d159`

## 目标

为设置页的 PostgreSQL 云端 JSON 恢复提供可预览、需二次认证、可检测并发变化的替换式恢复流程，封闭旧 `/migration/import-local` 可被空数据误触发清空账号数据的问题。

## 用户流程

1. 选择本地浏览器备份或完整 `domo-nav-backup` 第 1 版云端备份。
2. 服务端严格检查格式、集合、计数、ID、引用关系、图片归属和记录上限。
3. 显示当前云端数据与待恢复数据的数量、图片/加密笔记/公开分享风险。
4. 用户先下载当前云端备份作为人工恢复点；服务端同时签发与用户、会话和当前数据库状态绑定的短时回执。
5. 用户输入当前账号密码和确认文字 `恢复`。
6. 服务端重新验证短时计划、当前会话和数据库状态，再在单个事务内锁定恢复涉及的表并完成替换。

## 安全边界

- 请求体最大 16 MiB；单次最多 5,000 条记录、2,000 个附件，并按附件额外数据库工作量限制为 8,000 单位。该保守上限用于避免逐条恢复在持表锁时长时间阻断其他写入；扩大上限前必须先完成批量写入改造与真实 PostgreSQL 压测。
- 预览计划有效期 10 分钟，并通过 HMAC 绑定用户、登录会话、规范化输入和当前数据库状态。
- 恢复前安全备份回执有效期 10 分钟；执行接口强制验证，不能通过直接调用 API 绕过“先下载当前备份”门槛。
- 普通完整导出始终保留全部 JSON 数据，并标注当前文件是否满足第 1 版一键恢复限制；只有验证为可回灌的当前备份才会签发安全回执。超限文件仍可作为完整归档，但必须等待后续分片或流式恢复能力，不能用于本版替换恢复。
- 发现跨账号 ID、分享码或图片身份冲突时，预览只返回阻断原因，不签发可执行计划。
- 预览后任一受管数据发生变化，执行阶段返回 `409`，不会开始删除。
- 执行必须再次验证当前账号仍获批准、当前会话仍有效、当前账号密码、`mode: replace` 和确认文字。
- 执行阶段在表锁之后重新读取状态和冲突；任何检查失败都发生在首个 `DELETE` 之前。
- 恢复端点另有每用户会话每小时 12 次的持久限流；限流服务不可用时失败关闭。
- 旧 `/migration/import-local` 固定返回 `428 restore_preview_required`，不再保留旁路。
- 成功恢复、审计事件与数据写入在同一事务提交；错误会回滚，并返回不包含数据库细节的错误信息。
- UUID 在预览阶段统一为小写并按大小写不敏感方式检查重复；历史 `warm-dark` / `warm-light` 主题值会安全映射为 `dark` / `light`。
- 已删除或缺失且未被笔记引用的图片墓碑保留在完整导出中，但恢复时会明确跳过；若笔记仍引用这类不可用图片，预览会阻断。当前目录里同 URL 的 `deleted` / `missing` 状态也会在任何删除前阻断。
- 下载文件使用紧凑 JSON；后端用同一恢复约束校验规范化信封，并以最大长度密码、计划和安全回执构造最坏请求探针，避免标记“可恢复”的文件在实际提交时超过 16 MiB。
- 预览和执行锁内都会检测跨账号脏外键；执行同时锁定 `note_reminders`，防止删除当前账号分组或笔记时级联删除其他账号的导航、分享或提醒。
- 缺失的笔记数字 ID 在内存中显式分配；序列只在所有插入和成功审计之后同步。单次恢复最多让全局序列安全前移 100,000，避免异常备份耗尽全局 ID。
- 安全审计仅记录事件类型、结果、主体和影响条数，不记录密码、备份正文或密钥。

## 数据语义

- 当前只支持明确的 `replace`，不提供规则不清的合并模式。
- 替换分组、导航、笔记、自定义搜索引擎和允许导入的设置。
- 设置仅允许 `appConfig`、`theme`、`whisperBgImage`；Telegram、Token、密码、未知键和敏感键不导入。
- 备份没有 `appConfig` 时保留当前 AI 配置；包含 `appConfig` 时，现有 AI 密钥仅在目标地址未变化时保留，避免把旧密钥发送到新地址。
- 现有 `media_assets` 图片目录不删除；备份中的同账号图片元数据按 URL/ID 去重补充。
- 图片预览不显示虚假的“替换后差值”：仅分别展示当前保留数量与备份待补充数量，最终目录数量由去重结果决定。
- 图片 URL 必须属于当前账号的图床目录；该 JSON 恢复入口不用于把另一账号的图片所有权迁入当前账号。
- 备份中的图片删除队列状态不会直接恢复：被笔记引用的图片归一为 `active`，未引用图片归一为 `orphan`，避免恢复操作误触发图床删除。
- 图片二进制仍位于外部图床，不包含在 JSON 中。
- 公开分享默认不恢复；只有用户明确选择时才恢复 bearer 分享码。
- 加密笔记保留密文，但备份不包含密码校验值；仍需原加密密码解密。

## API

### `POST /migration/restore/preview`

```json
{
  "backup": {},
  "mode": "replace",
  "restoreShares": false
}
```

返回当前与待恢复计数和警告；只有不存在阻断冲突时才返回 `planToken` 和过期时间。该接口只读。

### `POST /migration/restore/apply`

```json
{
  "backup": {},
  "mode": "replace",
  "restoreShares": false,
  "planToken": "short-lived-signed-plan",
  "backupReceipt": "short-lived-safety-backup-receipt",
  "currentPassword": "user-entered-at-runtime",
  "confirmation": "恢复"
}
```

## 已验证与待验证

本地已通过纯 Node 语法检查和恢复校验/路由静态测试。由于本机工作树未安装项目 npm 依赖，完整 Fastify、PostgreSQL、Vue 构建由 GitHub CI 完成。CI 另设独立 `nav_restore_test` 数据库：测试脚本只有在 `NODE_ENV=test`、显式测试开关、localhost 地址和精确数据库名同时满足时才允许清理测试数据。

合并前至少验证：

- 空对象、缺数组、畸形标量、计数不一致、重复 ID/分享码/设置键/图片身份均在任何 `DELETE` 前拒绝。
- 错密码、过期/篡改计划、跨会话重放、预览后并发写入均不改变数据。
- 混合显式/缺失数字 ID 不冲突；异常大幅前移被拒绝；插入或审计失败时不会提前修改序列。
- 模拟最后一步插入或审计失败，当前账号数据完整回滚。
- 用户 A 的恢复不能读取、覆盖或引用用户 B 的数据和图片。
- 精确 5,000 条上限载荷必须真实恢复，并观察 8 张目标表的 `ShareRowExclusiveLock` 在 60 秒内释放。
- 双域桌面/手机完成文件选择、备份下载门槛、键盘焦点、分享开关与刷新验收。
