## 本地实现

- Passkey 前后端退役：配置固定 disabled/retired，其余旧端点 410；删除浏览器/服务端运行依赖，保留历史迁移与数据。
- 邮箱验证码登录、未登录找回、已登录邮箱改密；仅已审批、已验证绑定账号。首次绑定需当前密码和新邮箱证明，换绑需当前密码及新旧邮箱证明；不合并账号。
- 加法迁移 `047`：凭据版本、挑战、短期密码复核、一次性敏感操作授权、加密认证投递队列。旧密码、恢复码改密也撤销所有会话、旧挑战和恢复码。
- 六位随机码、数据库五分钟到期、同 flow 六十秒重发、五次错误锁定、事务一次性消费；PostgreSQL 配额共享，不因更换域名、用途或实例而重置。
- 独立 HMAC / AES-GCM 密钥，密钥版本与最长五分钟旧版本窗口；认证码不进入旧明文 outbox。系统 SMTP 生命周期独立处理认证队列，不启动个人邮件 worker。
- SMTP accepted 与实际收件分开；明确临时失败最多三次，DATA 结果不明不自动重发；过期、消费、撤销或凭据版本变化后的验证码任务不发送。
- 私有导出（含恢复前安全备份）、系统 SMTP/云备份/Provider/Telegram 配置需当前密码复核，授权绑定 session、凭据版本、方法和路径，仅能消费一次。恢复应用、OAuth 绑定/解绑和恢复码生成保留各自原有密码门禁。
- 登录页桌面双栏、移动单栏、邮箱/密码切换、Provider 条件显示、验证码粘贴与焦点、密码管理器兼容、服务关闭降级。账号安全增加邮箱绑定和改密；管理员可手动刷新不含身份明细的认证队列计数。
- 灾难恢复脚本在启动应用前撤销恢复出的会话/挑战/授权并清空待发送认证密文；本轮只改脚本并在隔离库测试 SQL，未执行生产恢复。
- 修复依赖锁文件中的 sharp / adm-zip 已知漏洞。当前 API 审计策略通过、前端与 API 审计零漏洞；不能推断旧生产镜像已修复。
